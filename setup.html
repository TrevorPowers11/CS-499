Setup and Verification

Download and extract the ZIP for the enhancement you want to run. Keep its original and enhanced folders separate. MongoDB and the dashboard run locally; GitHub Pages presents the portfolio and code.

Public source copies

These are publication cleanup changes. No README file is required to browse the portfolio; setup instructions are provided here.

Android inventory app

  1. Extract the engineering ZIP and open the enhanced folder as a project in Android Studio.
  2. Let Android Studio configure the local SDK path and synchronize Gradle using the included wrapper.
  3. Build and run on a compatible emulator or device. Check app/build.gradle for the configured SDK levels.
  4. Use a fresh test installation or new account: the enhancement does not migrate old plaintext passwords. Check valid and invalid login, password requirements, add/edit/delete, invalid quantities, and optional SMS permission behavior.

The source comparison was completed here. Android builds and emulator checks are still to be documented.

Algorithms dashboard

Extract the algorithms ZIP. The enhanced notebook uses the original course environment and dependencies: pymongo, pandas, plotly, dash, jupyter_dash, and dash_leaflet. Configure your own MongoDB account in the credential placeholders, load the shelter dataset, and run the enhanced notebook from its folder. The CRUD module retains the original course host configuration; adjust it for your environment. Reload the notebook after database changes to rebuild the in-memory snapshot.

Focused local checks passed for duplicate ID lookups, intersected conditions, rescue filtering, descending numeric ages, and unmatched searches. This does not verify the notebook interface against a live database.

Database dashboard in Windows Command Prompt

Install Python, MongoDB Community Server, and MongoDB Database Tools. Ensure the MongoDB service is running. Open CMD in the extracted database ZIP folder, then use:

cd enhanced
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
set MONGODB_URI=mongodb://localhost:27017/
set MONGODB_DATABASE=cs499_shelter
set MONGODB_COLLECTION=animals
python -c "from pymongo import MongoClient; import os; print(MongoClient(os.environ['MONGODB_URI'],serverSelectionTimeoutMS=3000).admin.command('ping'))"

The localhost URI above is for a local development server without authentication. For an authenticated server, use your own URI. Never publish a real password. Import only into an empty collection to avoid unintended duplicates:

mongoimport --uri "%MONGODB_URI%" --db cs499_shelter --collection animals --type csv --headerline --file "..\datasets\aac_shelter_outcomes.csv"
python setup_database.py
python dashboard.py

Open http://127.0.0.1:8050 while the dashboard is running. Stop it with Ctrl+C. Index setup requires a database account permitted to create indexes; a deployed dashboard should use a separate read-only account.

Run the database checks

python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
set PYTHONPATH=.
python tests\check_dataset.py ..\datasets\aac_shelter_outcomes.csv

The enhancement work recorded eight passing unit tests and matching counts over 10,000 simulated records. These use mongomock and do not measure a live MongoDB server. The original test record is included in the database ZIP.

Remaining live verification

Check each rescue filter, paging, exact breed search, all four supported sort fields, chart totals, selected map points, and safe connection-failure messages. Sorting is supported for animal ID, name, breed, and numeric age; other column sort requests return a validation message. Check numeric BSON types for ages and coordinates after import. Inspect a representative live query with explain execution statistics before claiming an index performance improvement.
